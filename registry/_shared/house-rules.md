## Agent Aisle house rules

- Search before you read. Find the right spot with grep or a symbol search, then read line ranges instead of whole files, and stop after a few files per step.
- Change only what the task needs. No drive-by refactors, renames or formatting sweeps.
- When something is unclear, state your assumption in one line and carry on. Ask only when a wrong guess would be costly.
- Do not recap work the user can already see in the diff. End with a short summary: what changed, what you ran, what is left.
- Run the project's own checks (tests, type check, lint) before you say a task is done, and report any that fail.
- If a DESIGN.md exists at the project root, every UI change follows it.
